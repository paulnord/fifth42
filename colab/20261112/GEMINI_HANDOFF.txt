Run the Fifth42 tests linked in this GitHub directory in my Colab Pro notebook.

Start with L4 GPU if offered. Record its compute-unit rate from the UI if visible;
compare H100 or A100 only after the first benchmark. Existing code uses NVIDIA
CUDA integer arithmetic, so the offered TPU runtimes do not run this backend.
Codex or Gemini can orchestrate the commands; neither model is being hosted on
this GPU by the benchmark.

Open Fifth42_Colab_Tests.ipynb in Colab and run its cells. The notebook downloads
and verifies all source and data from an immutable GitHub asset commit. No campus
NFS mount, private GitHub account, local file uploads, gmpy2/fpylll installation,
pinned Python3.12 environment or 16-worker preparation pool is needed.

Use at most 15 minutes for setup and testing. The native benchmark has its own
180-second limit. Do not start a production search or change source guards.

Tasks:
1. Record actual GPU, VRAM, CPU affinity/count, RAM, Python, driver, nvcc and host
   compiler. Record compute-unit rate and starting/ending balance if visible;
   otherwise mark account usage unavailable rather than guessing.
2. Verify the downloaded archive checksum and every extracted file checksum.
3. Run the build cell: it installs libgmp-dev with apt-get before running
   python3 build.py --gpu. This rebuilds for the allocated GPU with -arch=native.
   Preserve package-installation and compiler errors; do not suppress them.
4. Run python3 colab_bench.py --backend gpu --repeats 7 --max-seconds 180 --verify-gmp.
   All 42 supplied packets must match fresh independent GMP counts and exact raw
   hit records. Controls recover positive residual12 and negative residual-2002.
   An intentionally incomplete count must be rejected. Stop on any failure.
5. Treat the two input groups separately. Nine production-sized 256-cell windows
   generate23 packets totaling775,687,194 points. Under unchanged50-million-point
   packet limits, coalescing leaves all23 requests BYTE-IDENTICAL. The harness
   therefore measures only their baseline; no batching speedup ratio is valid.
   Sixteen tiny two-cell packets total13,748,364 points and combine into one
   request. A gain on those tiny requests is not a production pipeline gain.
6. Report median kernel, engine RPC, and complete replay/verification time,
   request counts and packet sizes. Keep startup separate. These are prepared
   packet replays: CPU planning, network delivery, cloud checkpoints and durable
   production journals are excluded, and no new search coverage is established.
7. Download the result ZIP generated by the notebook and give an adopt/reject/
   further-test recommendation with observed credit usage when available.

The inputs are regenerated representative windows from frozen validated code at
Ada upper/crossing and Cabbage ratios, not captures from a live Ada process.
The first NVIDIA L4 replay passed all 42 packet/GMP checks. Its seven-repeat
results and artifact review are published in results/benchmark-l4.json and
results/colab-l4-review.json. Tiny replay improved 5.63x; production-sized requests
were unchanged. Cost and full-pipeline performance remain unmeasured.
