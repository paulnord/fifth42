# Cabbage GPU preparation experiments — 10 November 2026

The GPU lattice prototype improved whole-pipeline throughput in one tested geometry region. Batching alone performed best in another. Production remains stopped and unchanged. These are finite TEST_ONLY experiments, not production coverage or a deployment recommendation.

All measurements below ran on **Cabbage**, RTX 3060 / Ryzen 5950X, with 16 physical CPU workers and local durable journals. “Ada”, “Cabbage” and “dense” name three representative geometry regions, not three benchmark machines.

| Geometry region | Current CPU, 1 window | CPU, 16 windows | GPU lattice, 16 windows | GPU versus batched CPU |
| --- | ---: | ---: | ---: | ---: |
| Ada, group 4 | 20,939 | 23,589 | 25,577 | +8.43% |
| Cabbage, group 8 | 36,814 | 41,401 | 38,917 | −6.00% |
| Dense, group 4 | 6,569 | 6,579 | 6,620 | +0.62% |

Values are median verified original logical cells/second from three balanced repeats, 32,768 cells per trial, 27 complete trials. GPU plus batching was +22.15% over the current pipeline in the Ada region; CPU batching was +12.46% in the Cabbage region. Dense differences are noise-scale. Three short repeats are preliminary evidence; Cabbage samples varied substantially. Full ranges, paired changes and startup-inclusive rates are in `results/AUDIT_MATRIX.json`.

Timing starts immediately before bounded preparation and ends after final durable journal close/flush. It includes preparation, worker IPC, native GPU enumeration, exact output checks, one independent GMP-audited 256-cell chunk per trial, and local durable commits. Worker/process/CUDA startup and the final full journal audit/reopen are outside this steady timing and are separately recorded. Existing scientific limits and native request sizes remain unchanged. GPU/CPU basis volumes need not match; each proposed basis is compared with its own GMP enumeration. Across these windows GPU point totals were slightly lower: Ada −0.005904%, Cabbage −0.005846%, dense −0.003868%.

The GPU computes candidate unimodular 3×3 transforms using double-double arithmetic. Workers retain their exact rational geometry, share only numeric GPU input/output buffers, reconstruct exact B=U*A, and run the unchanged independent exact certificate and native integer/point guards. A GPU proposal never supplies a trusted exclusion bound. Rejected proposals use the existing cold CPU preparation and guarded subdivision. A fixed optional exact LLL *quality* gate can be enabled; the optimized timings omit it because exact LLL is unnecessary for coverage completeness and its exact Gram–Schmidt cost exceeded the CPU LLL work it replaced. All 193 saved candidate transforms passed that gate with identical Tasks/certificates when it was omitted.

The selected matrix admitted **61,440/61,440** GPU proposals with zero fallback. All 27 checkpoints, committed journal chains, contiguous spans, native count checks, saved GMP audits, final flushes and recovery checks passed. Large-region hit sets were empty. Separate native/GMP/brute-force controls found all four known small-shell hits under groups 4/8/16. Nine integration gates also exercised the exact LLL option, safe subdivision, deliberately singular GPU U and iteration-status fallback. Additional tests passed: 8 certificate tests, 5 buffer tests, 4 no-LLL adversarial tests, 3 service/worker-failure tests, and CPU/GPU runs with a partial final window, partial 16-window batch and partial durable journal buffer (2,573 cells).

An independent reviewer audited every matrix result against its checkpoint and full journal, including SHA256 chains and saved GMP response files. No uncommitted journal suffix remained. CPU-only fault injection confirmed an explicit service failure returns no Task, and worker death/replacement fails closed with resource cleanup.

A separate adaptive-width CGBN integer Newton prototype substantially improves the previous root kernel. For 16,384 captured-shaped roots its kernel took 0.607 ms versus 9.221 ms with GMP; one persistent request plus independent exact GMP proof took **12.657 ms**, so the complete root path still lost. This batch repeats 384 unique inputs. On Dot’s mixed 4,092 cases (4,083 unique), the kernel was 0.370 ms, about 32× faster than the earlier bit-by-bit CGBN kernel, but request plus proof again lost. All 16 fixture correctness checks, 10,720 exhaustive CPU cases with six adversarial seeds each, and 21,440 bad-root rejections passed. A supplemental check passed 22 native malformed/unsupported packet cases and 15 explicit certified CPU fallbacks. The original final two-second root slot did not run native error cases; the supplement closes that gap using the exact same source/binaries. cuPQC Newton was not implemented or tested in this iteration; the earlier CGBN/cuPQC/GMP comparison is preserved in the parent revision.

Profiling explains the limited root benefit: the GMP root wrapper was only 0.79% of serial Cabbage group-8 preparation, and the complete bracket path 2.44%. LLL, exact bounds, independent certification and host transport are larger targets. The tested GPU path does not yet keep the GPU continuously occupied. Further work should reduce exact host preparation/transport overhead and evaluate larger, diverse windows before choosing a production policy.
