# Fifth-power lattice prototype

A small independently reviewed tangent-patch/lattice search for near-solutions of
`a^5+b^5-c^5=r`, with a documented reduction for the full signed equation
`x^5+y^5+z^5=42`. No production search, GPU job or deployment is involved. This directory is isolated from the existing exact-search and ADA production code.

## ADA handoff and evidence

Read [ADA_HANDOFF.md](ADA_HANDOFF.md) before working on ADA, and [PUBLICATION.md](PUBLICATION.md) for the source snapshot and publication scope. Published `results/` files are the original raw cloud validation evidence. Preserve them unchanged; reproduce in a separate scratch copy. No archive extraction is required.

## Run

Core code needs Python 3.10+ and the standard library, with no package installation:

```sh
python3 lattice5.py --bound 100 --mode signed42
python3 lattice5.py --bound 100 --mode healy
python3 -m unittest -v test_lattice5 audit_tests
python3 reproduce.py --bound 1000
```

The optional direct upstream comparison also needs an existing `g++` and GMP C++ development headers/library:

```sh
python3 compare_upstream.py
```

It compiles the frozen upstream CPU and GPU-row **CPU emulation** sources in `vendor/`. No GPU execution is claimed. The original Git blob hashes and URLs are recorded and checked in `vendor/SOURCES.json`. The comparison expects the included `results/healy-1000.json` and `results/signed42-1000.json`, or fresh versions generated by `reproduce.py --bound 1000`.

`./run_validation.sh` runs all checks and rebuilds the bounded results. The full script takes roughly two minutes on this environment. If GMP is unavailable, the standard-library implementation, independent audit tests and reproduction still run; the upstream comparator will fail clearly rather than substitute a different program.

## What was established

* Complete canonical positive near-miss search through c=1,000 with |r|<=5c^2: all 10 entries in the published Healy table in that interval recovered, with exact equality against a separate exhaustive (a,c) oracle.
* Complete signed target42 box through +/-1,000: no solution, agreeing with the independent signed dictionary oracle and the existing upstream GMP CPU implementation. This is only a regression overlap, far smaller than prior ADA work.
* Nonempty controls target12 and target2951 through +/-100 also agree with actual upstream code. All four 192-bit row variants run by CPU emulation are checked, with and without the relevant modulo11 filter for target42.
* Two explicitly fixture-selected patches recover published large examples at c=27,580,409 and c=24,482,314,857. They exercise exact large-integer arithmetic and enumeration but **do not cover either full denominator shell**.
* Ten implementation tests plus seven independently written audit tests pass, including rational endpoint and residual-boundary cases, repeated bases, unimodular reconstruction, exhaustive lattice enumeration, and fail-closed work guards.

Read `COVERAGE.md` for the completeness argument and assumptions; `AUDIT.md` for the independent review. `RESULTS.md` summarizes actual timing and limitations. All run outputs are in `results/`.

## Meaning of complete

`complete:true` means this implementation completed the stated finite domain under the argument in `COVERAGE.md`; it is not formal verification or a global mathematical nonexistence theorem. Guards abort with `complete:false` and nonzero exit status. Shared patch boundaries are covered inclusively and duplicate exact hits are deduplicated. Only integer/rational comparisons make exclusion decisions.

## Sources

* [Noam Elkies, Rational points near curves and small nonzero |x^3-y^2| via lattice reduction](https://arxiv.org/abs/math/0005139).
* [Alex Healy's published Fermat near-miss table](https://www.alexhealy.net/papers/fermat/fermat.html). The five-power cutoff |r_score|>=1 is equivalent to |a^5+b^5-c^5|<=5c^2. Our residual sign is opposite his table's denominator sign.
* [Existing fifth42 exact search](https://github.com/paulnord/fifth42/tree/main/extended/src). Frozen file identities are recorded in the artifact.

This is an implementation inspired by the method, not a reproduction of the authors' source code or an audit of their complete searches.

## Optional published reduction backends (bounded experiment)

Install optional pinned dependencies from `requirements-sympy.txt` and/or
`requirements-fpylll.txt`, then select `--backend sympy` or `--backend fpylll`.
The default `reference` keeps the dependency-free original implementation.
Run `python3 -m unittest -v test_lattice5 audit_tests test_backends` and
`python3 benchmark_backends.py` to reproduce paired exact controls and timings.
See `THIRD_PARTY.md` for provenance, licenses and the exact safety boundary.
Run `./run_validation.sh --published-backends` for the aggregate original plus
optional-backend suite and both benchmarks (both pinned optional dependencies
must be installed). Without that argument the original validation remains
standard-library-compatible, apart from its existing GMP C++ comparison.

The optional modular and enumeration experiments are documented in `MODULAR_FILTERS.md` and `ENUMERATION_OPTIMIZATIONS.md`. These include measured negative results as well as improvements; no experimental mode is silently enabled.

Start with `CURRENT_RESULTS.md` for the consolidated new findings. The separate optional compiled-rational experiment is documented in `COMPILED_RATIONALS.md`; it does not change the default modules.
